# 防幻觉方法全景分析

> 2026-05-31 | 来源：豆包 + DeepSeek 交叉分析 + CMG v5.6.0 现状对照

## 幻觉分类（两份来源一致）

| 类型 | 描述 | CMG 当前能力 |
|------|------|:--:|
| **假性幻觉（偷懒）** | 模型清楚自己没查，图省事编造 | ✅ 拦得住 |
| **真性幻觉（认知篡改）** | 模型真心以为自己查了/验证了，记忆时序错乱 | ❌ 拦不住（坑点 29） |

## 豆包 6 方案 vs CMG 可行性

| # | 方案 | CMG 现状 | 可行？ |
|---|------|---------|:--:|
| 1 | RAG 知识库固化事实 | rules/ 只管规则，不管通用事实 | ⚠️ 可扩展 |
| 2 | 行为溯源校验层 | post_llm_call 已有证据校验 + 外部主张验证 | ✅ 已部分实现 |
| 3 | 双模型分流 | memory 有偏好但非自动化 | ⚠️ 配置层 |
| 4 | 思考链强制外化 | 管不到 LLM 内部推理（坑点 29） | ❌ 管不到 |
| 5 | 对话记忆轻量化+时序分段 | Hermes 基础设施 | ❌ 非 CMG |
| 6 | Harness 驾驭外壳 | sentinel 就是 Harness，已做 70% | ⚠️ 持续迭代 |

## DeepSeek 全景图分类

```
1. 模型训练与微调        → 模型层，非 CMG
2. 推理与解码            → 推理层，非 CMG（坑点 29）
3. 检索增强生成 RAG       → 可扩展（Self-RAG / Corrective RAG）
4. 外部知识约束           → 可扩展（KG / API）
5. 系统架构与流程          → CMG 主战场 ✅
6. 后处理验证             → 已部分实现 ✅
```

## CMG 可落地优先级

### 第一梯队：零外部依赖，立即可做

1. **方案 2 升级 strict 模式** — post_llm_call 无行为日志→直接丢弃输出（不给重试）
2. **CoVe 自检注入**（DeepSeek 提的 Chain-of-Verification）— post_llm_call 追加"逐条验证你刚才说的"
3. **pre_llm_call 事实注入**（方案 1 轻量版）— 自动检索 rules/ + memory 关键事实注入上下文

### 第二梯队：需要新增模块

4. **Self-RAG 风格触发**（= pre_llm_call 素材自动预拉取，已在 CMG 计划中）
5. **多 Agent 验证**（远期）— delegate_task 验证子 Agent

### 做不了的

- 模型训练/微调 → 模型层
- 推理层干预（DoLa/Lookahead）→ Hermes 内核
- 思考链外化 → 推理黑盒

## Harness 外壳对照（sentinel vs 理想 Harness）

| 豆包定义的 Harness 应该 | sentinel 现状 |
|-----------------------|---------------|
| 独立于大模型思维之外 | ✅ Plugin 层 |
| 独立判断 | ✅ post_llm_call 证据校验 |
| 独立记忆 | ⚠️ 只读 rules/，不独立 |
| 独立行为监管 | ✅ pre_tool_call 拦截 |
| 审判真假 | ⚠️ 只做文本模式，不做语义真假 |
| 约束行为 | ✅ 17 hooks |
| 管控诚实度 | ⚠️ 只管输出，管不到推理 |

## 两份来源的核心共识

一致结论：**Harness 外壳 + RAG + 验证层**是 Agent 防幻觉的现实路径。

- 模型层方案（训练/微调/解码）→ 用户不可控
- 系统架构方案（隔离/校验/多 Agent）→ CMG 主战场
- 后处理方案（CoVe/交叉验证）→ sentinel 核心功能
