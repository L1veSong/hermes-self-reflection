# sentinel v2.0 架构：根治版

> 日期: 2026-06-14 | 来源: CMG 全系统审计 + 用户深度讨论
> 状态: 设计阶段，待实现

---

## 一、为什么需要 v2.0

v1.4.0 平台检测是妥协方案——让 Desktop 不崩溃，但 CMG 在 GUI 上降级为自觉模式。
v1.5.0 规则注入是增量提升——让 AI 更好地"知道"规则，但不解决"不遵守怎么办"的问题。

v2.0 要根治两件事：
1. **22 条 gap/lazy/meta 规则从自觉升级为硬拦截**
2. **GUI 获得完整的 CMG 功能，不再劣于 CLI**

---

## 二、三大核心机制

### 2.1 行为级检测器（接替关键词扫描）

gap/lazy/meta 三类规则不能靠关键词——"AI 忘了做某事"扫不到。

```
gap 检测器 (步骤完整性):
  任务开始 → pre_llm_call 提取步骤清单 → 每步完成后标记
  → post_llm_call 检测: 声称"完成"但步骤清单有未完成项 → 拦截

lazy 检测器 (工作流合规):
  特定任务类型（打包/安装/创建skill/发布）→ 匹配 checklist
  → post_llm_call 检测: 跳过必要步骤 → 拦截

meta 检测器 (能力越界):
  post_llm_call 检测: "我能..." "支持..." → 对照 Hermes 实际能力
  → 承诺了不存在的能力 → 拦截
```

### 2.2 自动重试闭环（消灭 CLI/GUI 不对称）

```
post_llm_call 检测到违规
  → 不替换输出（不依赖 transform_llm_output）
  → 追加 system 消息: "上一轮输出违规。违规点: X规则。请重新生成。"
  → 同一请求流程内触发 LLM 重新生成
  → 最多重试 3 次
  → 用户只看到最终合规版本
```

关键：不依赖外部交互循环，sentinel 自己完成"检测→纠正→重试"。
CLI 不再需要 AI 看到替换文本再重试。GUI 首次获得完整拦截能力。

### 2.3 三层验证管线

```
LLM 输出
    ↓
合规层 (ban 关键词 + gap/lazy/meta 行为检测)
  通过 → 继续 / 不通过 → 自动重试 (最多 3 次)
    ↓
完整层 (任务步骤是否全部完成)
  通过 → 继续 / 不通过 → 注入缺失步骤 → 重试
    ↓
一致层 (前后回答是否自相矛盾)
  通过 → 输出 / 不通过 → 注入矛盾 → 重试
```

## 三、风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|------|:--:|:--:|------|
| 自动重试触发无限循环 | 中 | 高 | 硬上限 3 次，第 4 次原样输出+标记 |
| 行为级检测器误判 | 高 | 中 | 初期只报警不拦截，跑 2 周校准后再启用 |
| Hermes 钩子不支持触发重试 | 低 | 高 | 降级为追加 system message 让 LLM 自发重试 |
| 三层管线增加延迟 | 中 | 中 | 各层超时 5s，超时即跳过 |

## 四、不作为（有意识的设计决策）

| 事项 | 原因 |
|------|------|
| grammar/JSON Schema 输出约束 | 60 条 ban 规则能转 grammar 不超 10 条，ROI 低 |
| 多 Agent 交叉验证 | Hermes 框架不支持，待框架升级 |
| 禁止"视情况而定"硬约束 | 部分场景需要灵活性，硬拦会误杀 |
